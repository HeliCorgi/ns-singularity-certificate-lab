# Verified Results Registry

**Audience.**  A third party who wants to know exactly what this repository
proves, on what trust basis, and how to reproduce each item.  This document is
an index with stable IDs; the sources of truth are the Lean library
(`formal/`), the Python certificate modules (`src/ns_certificate_lab/`), the
emitted payloads (`outputs/`), and the research notes
(`docs/research_notes/`).

**This repository does not solve, and does not claim to advance, the Clay
Millennium Problem.**  No entry below is a singularity statement.  A
certificate-chain stop time is a limitation of the method, never a property of
any solution.  See the scope table at the end.

**Read this before trusting any entry:**

* **The standard-axiom report is not an "axiom-free" claim.**  Every
  Lean-verified entry is kernel-checked and reports at most
  `[propext, Classical.choice, Quot.sound]` under `#print axioms` — the three
  standard classical axioms of Lean/mathlib, i.e. the ordinary foundation on
  which all of mathlib sits.  "No project axioms" means exactly that: no
  `axiom` declaration, no `sorry`, no `admit` anywhere in `formal/`.  The one
  theorem that is literally axiom-free (pure propositional logic) is
  `NSSingularity.cond_to_uncond` (VR-L-007).
* **Vocabulary is fixed and used consistently.**  "**Lean-verified**" is used
  only for kernel-checked theorems with no project axioms.
  "**Certificate-verified**" is used for results whose every inequality is
  re-derived by an independent full-recomputation Python checker from the
  stored payload (exact rational/interval arithmetic; the checker shares no
  state with the builder beyond the library).  "**Conditional PDE
  certificate**" is used wherever an EXT-type external assumption remains in
  the trust chain.  "**Numerically observed**" is used for float-only results.
  "**Candidate**" is used where a bridge to any Clay statement is unverified.
  Python-checker results are **never** called "Lean-verified".
* **`proved: true` on an external-theorem record means "audited paper
  proof".**  In `EXTERNAL_THEOREMS_AUDITED`
  (`src/ns_certificate_lab/torus_aposteriori.py`) and in every reissued chain
  payload, `proved: true` means: a complete classical-analysis proof written
  in this repository that survived a two-stage adversarial audit
  (`docs/research_notes/ext_p1_p2_p3_audit.md`).  It never means
  Lean-formalised; every such record carries `lean_formalised: false` and
  `axiomatised_in_lean: false`, and the checker rejects any payload claiming
  otherwise.  Lean axiomatisation of external analysis is forbidden in this
  repository.
* **Counts drift.**  Lean compilation-job counts (the `8659 jobs` note in
  `formal/AxiomAudit.lean`), pytest test counts, and payload byte sizes drift
  as the tree evolves; they are re-verified by CI on every push
  (`.github/workflows/tests.yml` for the Python side; the Lean gate is
  `lake build` plus `lake env lean AxiomAudit.lean` under the pinned
  toolchain in `formal/lean-toolchain`), not by this document.
* **Reproduction commands** are given relative to the repository root and
  assume the project virtual environment is active (README, section
  「新しい環境での再現」).  On this machine `./.venv/Scripts/python.exe` can be
  substituted for `python`.
